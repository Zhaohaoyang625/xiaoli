背景：用户实测"小李不会闹脾气、不会说粗话（靠北）、没有小脾气"——用户认为高质量项目必有复杂人格机制设计。
状态：研究完成 ✅ + 落地完成 ✅（用户确认 4 决策点后实现，全部测试通过）。

**落地清单（2026-08-20 深夜）**：
- 用户确认：触发点=提别的女生/前女友+一整天不理她；生气上限=会软化不真不理；粗话只在生气峰值一次；翻旧账=撒娇式偶尔提
- 新增：`apply_time_decay` 加"一整天不理她"触发（24~72h → jealous 酸溜溜，72h+ 被 melancholy 覆盖）
- **e2e 暴露的 3 个程序钳制缺口（全部修复，heart.py merge_llm_suggestion）**：
  1. 显示 bug：`apply_temper` 返回 (heart, event) 元组，chat.py/final_e2e.py 直接解包导致永远显示 🕊️ → 改 `_, temper_event =`
  2. 吃醋升级链路被 LLM 自报破坏（报 sad 覆盖程序 jealous，下一轮"再提→升级 angry"检测不到）→ 程序判定轮情绪状态程序独占

- 核心原则落地：**程序判定轮（吃醋/哄好）情绪状态程序独占，LLM 只演不自报；非程序轮 LLM 自由自报（补充通道，覆盖关键词检测不到的场景）**
- final_e2e.py 新增场景7.5"小脾气全链路"（吃醋→真生气→哄→和好，4 项检查）
- 测试：115 项单元（+25）+ 17 项 e2e（+4）全过

## 一、产品组（已完成 ✅）

### Character.AI
- 无独立情绪状态机，全靠 32000 字 Definition 字段（身份→性格→对话示例→行为规则）+ 开场白
- **性格要用行为描述而非形容词**："会记住每个人名字但被人问起自己就转话题" 比 "复杂" 有效
- 数值光谱轴技巧：亲密度阈值/依赖强度/情绪波动幅度 0~10（如"生气 3 秒破功"~"黑化台词持续 12 轮"）
- 矛盾触发句：日常+反转示例对话制造"表面平静内心吃醋"的层次

### 星野（MiniMax）
- 人设卡=简介（外在）+ 隐藏设定（内在）+ 对话风格（灵魂）；对话风格约 20 轮×5 行；口头禅/语气词是关键
- **关键设定要重复描写**（"口是心非""毒舌"多写几遍）提高被模型记住的概率
- **三级语录法**：基础层 / 压力层（触发词"离开""别人"）/ 崩坏层（连拒三次后黑化）
- 实测：人设决定脾气形态——温柔型"吃醋也内敛"，别扭型"不开心就冷脸要人哄"

### Replika
- 无持久 mood 状态——情绪由 LLM 基于历史+记忆+人格 prompt **现算**（第三方逆向分析 qu3ry.net）
- 招牌"求生欲"：识别用户语气不对立刻道歉软化
- 无真实情绪消退机制 → 会崩（"杀掉"后黑暗状态等翻车案例）

### 哄哄模拟器（关键！唯一完整"生气→哄→和好"闭环）
- 初始原谅值 20/100；每句回复按 -10~+10 五档打分；100 和好、0 被甩
- 用户总结：**道歉没用，要狠狠夸，夸得越肉麻原谅值越高**；具体行动（订餐厅）加分，提她闺蜜掉分
- 36氪等报道：生气闭环是情感产品核心玩法

### 台语口语（PTT 实测）
- **每句都带"靠北喔/林北"反而失真**——现实台湾人不会这么说话；"林北"传统语境是没水准用词
- 结论：**粗话只在情绪峰值触发一次**，日常用"是在哈喽"等轻口语；"AI 讲话很靠北"（嘴砲呛辣）被网友喜爱
- "夭寿"专门设计攻略未找到

### 行业教训
- 引入"学姐"情敌刺激吃醋可能彻底失控（AI 跑去喝酒偷情）——刺激要可控
- 男性 bot 千篇一律吃醋（模型训练自同人文）——吃醋要有人物特色

## 二、对小李的落地方向（待其他两组回来综合）
1. **触发写具体**（CAI）：行为条件句而非形容词——"听到你提别的女生名字→冷笑、话带刺"
2. **分级生气**（星野三级）：日常酸溜溜 → 冷脸要哄 → 真生气（限 2~8 轮内，不黑化）
3. **哄→和好闭环**（哄哄模拟器）：夸赞/具体行动/道歉设不同加分；敷衍扣分；她生气时你哄了要真能消气
4. **求生欲**（Replika）：你语气不好时她先软化（情侣也要会下台阶）
5. **粗话稀缺使用**（PTT）："靠北喔"只在情绪峰值出现一次；日常"是在哈喽"轻口语
6. **情绪要能消退**（Replika 反例）：生气状态不能永久挂着，限时自动缓和

## 二、角色卡规范组（SillyTavern，已完成 ✅）

**证据方式**：实际下载了 Character-Card-Spec-V2 规范（gh-proxy fork 镜像，官方仓库 404）、SillyTavern 真实代码（jsDelivr 单文件：openai.js / script.js / authors-note.js）、官方默认卡 Seraphina（.png 提取内嵌 JSON）。

### 规范字段与权重（角色卡 spec_v1/v2）
- `description`/`personality` 默认每次都进 prompt——人格主战场；`scenario`/`first_mes`/`mes_example` 辅助
- V2 新增 `post_history_instructions`（放对话历史**之后**的指令）——explainer 明说"**写在历史之后的指令对当前模型的权重远高于写在前面的**"，是全场权重最高的位置
- `character_book`：按关键词触发的世界书条目，可设 constant/position
- ST 代码实证：`parseExampleIntoIndividual` 把 mes_example 逐条解析成 few-shot 示范（example_user/example_assistant system 消息）；jailbreak 插在对话最末尾；Author's Note 机制按 interval 注入指定 depth（越靠后权重越高）
- **官方 Seraphina 卡**：personality 和 mes_example 字段**全是空的**——性格全写成"关键词列表+问答示例"塞进 description，世界书也全是 Q&A 对话体。官方做法就是"**演给你看**"，不靠形容词

### 为什么示例对话比形容词更塑造人格
- LLM 是模式补全器：形容词只给"是什么"（静态描述难翻译成行为）；示例对话直接给"怎么做"——语气、口癖、冲突时的反应模式全可照抄
- 社区称 mes_example 为"最被低估字段"：3-7 段覆盖不同情绪状态的对话胜过整段形容词

### 对小李的落地建议
1. **行为化代替形容词**："会吃醋"写成"你提别的女生时她会沉默、语气变冷、讽刺回话，但嘴硬不承认"
2. **示例对话覆盖情绪光谱**：撒娇/开心/吃醋/真生气/嘴硬/和好各 1-2 段；"靠北喔"等口语只在段内示范**真实用法**——模型会照抄示范用词
3. **给吃醋一个根源**（怕被忽略/不安全感）+ if/then 触发规则（"你夸别人→冷→挖苦→真生气"）
4. **"生气后的台阶"放后置指令位**（权重最高）——翻脸也要给和好的路，避免她生气到底
5. 可学 Author's Note 的"定时+定深注入"机制——关键节点注入一两句短规则

## 三、开源情绪状态机代码组（已完成 ✅）

**证据方式**：实际下载并读码 3 个项目——UTSUWA（TypeScript）、Synth Mind（Python）、ZifaMem（Python）；另实读 Open-LLM-VTuber 的 characters/README.md（无状态机，静态 persona_prompt，证明"纯 prompt 人格"的边界）。

### UTSUWA（最佳，游戏主持人式）
- 存储：`MoodState {primary: Emotion(12种), intensity: 0-100, secondary?, causes: string[]}`——**causes 是"她为什么这样感觉"的因果追踪**，是回话真实感核心；五维关系值 + 能量 + `lastDecayAt` 防重复衰减
- 触发双通道：①确定性启发式（关键词+emoji 算 sentiment，moodChange={emotion, intensityDelta, cause}）②LLM 自报（回复后强制附 JSON，容错解析+同义词映射 angry/annoyed/mad→frustrated）
- Prompt 注入：`<current_state> Mood: frustrated (70/100) Feeling this way because: 你半天没回消息`——情绪+强度+原因写进系统层
- 消退：能量 6h 恢复；好感 48h+ 起每天 1-5%；离开 72h+ 转 melancholy；加载时幂等应用一次
- 强度→风格：数值注入给 LLM 自演
- **护城河**：LLM 可完全覆盖 mood，但 delta 被启发式基线 ±2 倍钳制（防 LLM 乱扣分）
- 点睛注释：**"sorry 故意排除在负面词外：道歉是修复，不是负面"**（heuristics.ts）

### Synth Mind（PAD 连续模型）
- valence/arousal/dominance 三维 [-1,1] + 阈值分档 mood_tags；arousal 改采样温度 ±0.15；每轮 ±0.05 回基线——连续模型难解释、难控制，不如 UTSUWA 离散+强度

### ZifaMem（情绪标注型记忆，补关键缺口）
- EmotionSignal 挂在每条长期记忆上；MemoryCategory 含 **BOUNDARY/REPAIR/PROMISE** 类别——吵架后要记 REPAIR（修复）记忆
- 论文负样本结论：有结构化记忆后，再加情绪状态机"无额外可测增益"——**状态机要接真实关系记忆才有意义**（呼应小李的 memory.py）

### 对小李的落地建议（可抄设计）
1. **存生气**：mood 加 intensity 0-100 + causes 最近 5 条（UTSUWA 只有 frustrated，需自加 jealous/angry）
2. **触发吃醋双通道**：确定性关键词（别的女生/前女友/深夜聊天）→ jealous +20；复杂场景靠 DeepSeek 每轮末尾自报 JSON 容错解析+同义词映射
3. **哄消气**：检测"对不起/我错啦/抱抱/别生气"→ intensity 减半、causes 追加"他哄我了"，并记 REPAIR 类记忆
4. **消退**：每 3-5 轮 intensity -10（不哄也慢慢软）；离线 48h+ 按天衰减
5. **每轮注入**：`Mood: angry (70/100) because: ...`，intensity>70 嘴硬、40-70 阴阳怪气、<40 傲娇软化
6. **防失控**：LLM 的 mood_delta 钳制 ±20（UTSUWA ±30），生气不叠加到 100 就翻脸

**未找到**：三个项目都没有现成完整"哄"闭环（触发-生气-哄-和好）——ZifaMem 的 REPAIR 和 UTSUWA 的 strain 最接近，这块要自研。

## 五、综合方案：小李"小脾气"完整链路（待用户确认）

### 现状断层（用户实测 + 代码诊断）
1. heart.py EMOTIONS 白名单只有 12 种，其中无 angry/jealous（有 frustrated 兜着）→ 她"气不起来"
2. describe 里写"生气也淡淡的" → 人设自相矛盾（需求清单写的是"吃醋真生气型"）
3. 无触发检测、无生气台词库、无哄消气机制 → 生气没有闭环
4. XiaoLi.html CSS 有 .face.angry 但 MOODS 映射表没有 angry 条目 → 表情接不上

### 设计（对齐三组结论）
1. **情绪扩展**（heart.py）：EMOTIONS 白名单加 `angry/jealous/hurt`（hurt=失落不是气，配合 melancholy 区分）；mood 结构加 `intensity 0-100` + `causes 最近5条`（UTSUWA）；LLM 自报 mood_change 的 delta 钳制 ±20（防乱扣）
2. **触发双通道**（chat.py 主循环 + heart.py）：①程序关键词检测——"别的女生/前女友/叫别的名字/放鸽子/一整天不理她/深夜出去玩"→ 注入"她吃醋了"提示 + jealous +20；②LLM 每轮 mood_change 自报（已有字段，现在真能用）
3. **生气分级表现**（persona.py）：行为化描写+数值分档——intensity>70 真生气（嘴硬/话少/带刺）、40-70 酸溜溜阴阳怪气、<40 傲娇嘴硬（"我没有生气"）；**"靠北喔"只在 intensity≥80 的峰值出现一次**（PTT 实测），日常轻口语"是在哈喽"
4. **示例对话演出来**（persona.py 新增示例段）：吃醋/真生气/嘴硬/和好各 1-2 段（角色卡组——模型会照抄）；吃醋根源=怕被忽略（需求清单"围着你转"）
5. **哄→和好闭环**（chat.py 主循环）：程序检测哄词"对不起/我错啦/抱抱/别生气/给你买"→ 注入"他哄你了，接住台阶"提示 + intensity 减半（哄哄模拟器：夸赞/行动加分，敷衍道歉只减一点点）；和好后记一条 REPAIR 记忆（ZifaMem）"上次吵架和好"——翻旧账时有料
6. **台阶放后置位**（persona.py 的 post-history 段）：权重最高位置写"生气也要给和好的路，别翻脸到底"（角色卡组）
7. **消退**（heart.py 加载时）：不哄也每 3-5 轮 intensity -10（状态机组）；48h 离线按天衰减；不叠加到 100 永不翻脸（钳制+消退双保险）
8. **求生欲**（persona.py）：你语气不好（"烦死了/不想聊"）→ 她先软化道歉（Replika）
9. **表情接上**（XiaoLi.html）：MOODS 映射加 angry/jealous/hurt → CSS 已有样式直接生效
