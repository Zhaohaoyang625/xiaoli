# 小李"住在屏幕里的人"——Live2D 活人化方案

- 日期：2026-08-22
- 依据：三条研究线（学术论文 / 三个高星开源项目源码 / 自家 web/ 基线盘点）
- 基准配置：RTX 5060 8GB + DeepSeek API 大脑 + 浏览器 Live2D（2D 骨骼动画不吃显卡，**配置完全无压力，瓶颈在素材与编排逻辑**）
- 材料归档：`docs/research/sources/live2d-alive/`（airi/、vtuber/、vtuber_web/、df_*.ts 全源码可翻）

## 一、研究结论先行（凭什么这么做）

| 结论 | 出处 | 对我们的含义 |
|---|---|---|
| **动作质量对"拟人感"的贡献 ≈ 面孔呈现的 6 倍** | SIGGRAPH 2026 Reality Check（变换动作来源 vs 7 种面孔渲染做对照实验） | 先修动作层，表情维持现状即可；换脸/加细节是浪费 |
| **微动最硬：呼吸/眨眼/重心摆动显著提升"活"感；虚拟人静止=雕像** | Scientific Reports 2021 + 待机动画可信度研究 2025 | 待机时她必须"活着"，这是第一步 |
| **手势库"多样性"远大于"有没有手势"** | IEEE Access 2025（无手势 vs 56 个 vs 2000+ 手势三档评测） | 手写足够大且**不重复**的行为库 + 随机轮换，不跑生成模型 |
| **身体跟节奏、脸跟内容** | TalkSHOW（脸与语音相关，身体只跟节奏相关） | 重音/句边界驱动身体动，内容只驱动口型表情 |
| **情绪→姿势有量化配方** | IEEE TAFFC 2023 综述（悲伤=幅度小+重心低+速度慢；愤怒=幅度大+速度快+不对称） | 直接翻译成 Live2D 参数曲线，不需训练 |
| **口型与情绪必须解耦**（情绪做在口型外=眉毛/头/身体参数） | Audio-Driven Facial Animation 综述 2024 | 我们现状已符合，保持 |
| **2D 风格化在恐怖谷安全区；别为"更真"推写实脸** | 恐怖谷元分析 2022（脸扭曲是最大诱发源） | 保持现有动漫风 |
| 3D 骨骼扩散手势模型（DiffGesture/TalkSHOW/EMAGE）**全部排除** | GENEA 评测（语义贴合至今没人做好）+ 无骨骼映射 | 不碰深度学习生成路线 |

开源项目对照（全部拉到源码，非 README 推断）：
- **Project AIRI**（Neuro-sama 复刻，2万+ star）— 活人感最强参照：插件化帧更新管线（表情/眨眼/口型永远叠在动作之上）、眨眼状态机、眼珠扫视、口型接管收尾、表情 duration 自动回退。**抄它的待机三件套**。
- **DesktopFriends** — LLM 函数调用驱动动作的教科书：模型分析器解析全部动作→按情绪动态生成工具描述→接 LLM。**抄它的模型分析器**（换模型零配置）。
- **Open-LLM-VTuber** — 内联 `[标签]` 方案（我们已踩过标签自报覆盖坑，只作对照）；model_dict.json 数据驱动格式可借鉴。
- 三项目共识：**贴图级换装不可行**（Cubism 无运行时换贴图 API），换装=模型变体切换；道具=exp3 参数开关或 Pixi 层叠加。

## 二、能力基线（自家 web/ 盘点）

**已有**：`beforeModelUpdate` 每帧钩子、表情系统（自写 angry/jealous/anxious + f02/f03/f04）、口型同步（MOUTH_OPEN_Y）、情绪→motion 联动（idle/flick_head/shake 三组防重播）、参数注入基础设施（setParamFloat + getParamIndex 保护）。

**关键发现：Shizuku 模型的身体参数全在，只是没人驱动**——PARAM_BODY_ANGLE_X/Z、BODY_X/Y/Z、ARM_L/R、HAND_L/R、BREATH、ANGLE_X/Y/Z 都在 .moc 里（idle motion 已引用），加身体动作 = 在注入函数里多 set 几个参数，**零美术资产**。

**缺口**：① 身体参数无运行时驱动；② motion 文件残缺（shake 1个/tap_body 1个/pinch 0个）；③ 待机写死（只播一次 idle）；④ 无换装管线；⑤ 点击交互没开（autoInteract:false）；⑥ 口型幅度纯随机（0.55+random*0.35），不联动情绪强度。

## 三、方案分层

### P0 活人感地基（纯代码、零美术资产，推荐先做）

**① 微动三件套状态机**（抄 AIRI `motion-manager.ts` 眨眼/扫视逻辑，落到现有 beforeModelUpdate 钩子）
- 自动眨眼：随机间隔 3000–8000ms、闭眼 75ms（easeOutQuad）、睁眼 150–300ms（easeInQuad）；**乘性调制**（基准 × blinkFactor）避免"没眨眼曲线的模型卡 0"；闭眼表情时跳过
- 眼珠扫视：加权随机间隔约 1s，取 PARAM_EYE_BALL_X/Y 目标 + 0.3 lerp 平滑逼近（模拟真人扫视节奏）
- 呼吸/重心微摆：低频正弦/Perlin 驱动 PARAM_BREATH + BODY_ANGLE_X ±1~2°，平静时幅度小、情绪强时幅度大

**② 说话时身体跟节奏**（TalkSHOW 原则落地）
- 句边界/流式每句开始时：BODY_ANGLE_X/Z 小幅起伏（配合现有流式朗读管线，读一句动一下）
- 口型幅度联动 intensity：激动时 mouthLevel 上限提到 0.9，平静时降到 0.5——口型不再纯随机

**③ 口型接管收尾**（AIRI 的 useMotionUpdatePluginLipSync）：说话结束 200ms smoothstep 释放 + 500ms 强制闭嘴再交还动作层——解决"待机动作曲线残留张嘴值"

**④ 表情自动管理**：expression duration 自动回退（`expression_set("腮红",0.7,3)` 3 秒后自动清）+ 30 秒表情自动重置定时器（LLM 忘复位时的兜底）

**⑤ 待机状态机**：30–60s 无输入时随机播 flick_head（甩头）/shake（摇头）+ 补写 2~3 个 .mtn（文本格式可手写），播完回 idle；**动作库轮换不重复**（多样性 > 有无）

- 成本：几小时代码（单文件 XiaoLi.html 内）+ 手写 3 个 .mtn
- 验收标准：不说话时她"活着"（眨眼/呼吸/眼神游移），说话时身体跟着节奏动，说完嘴不会残留张开

### P1 行为编排（LLM 驱动，接现有 DeepSeek 函数调用链路）

**⑥ 模型分析器**（抄 DesktopFriends `modelAnalyzer.ts`）：加载模型时解析 FileReferences.Motions 全部动作→规则情绪映射（中文语义词表直接可用，可选 LLM 批量分析兜底）→按情绪分组生成 playMotion/setExpression/resetExpression 工具描述注入 DeepSeek——**换模型零配置，动作库自动跟着变**

**⑦ 情绪×动作行为库**（TAFFC 因子翻译成参数曲线）：
- 生气：幅度大+速度快（BODY_ANGLE 大幅晃动+甩头 flick_head）
- 难过：幅度小+重心低（身体下沉 BODY_Y 负值+低头）
- 开心：歪头（ANGLE_Z ±4°）+ 轻快小动作
- 结合现有"情绪指令·必做"（spoken 一句 + continuation）扩展动作维度——说话与动作统一

**⑧ 点击交互**：开 autoInteract + 补 tap_body/pinch motion（摸头/捏脸/戳脸各有反应），hit 区域按部位配置（头/身体分开）

- 成本：中（一次工具接入 + 行为库调参几小时）
- 验收：她说"哼！"时真的甩头背过身，摸她头会歪头蹭一下

### P2 演出层（道具/换装/特效——资产决定，可后置）

**⑨ 配件 = exp3 参数开关**（AIRI 做法，零美术）：把"戴猫耳/脸红/水手服 ON"做成 exp3 组，LLM 用 expression_set(name, true, duration) 编排，duration 自动回退

**⑩ Pixi 层特效**：爱心/气泡/花瓣作为独立 Pixi 精灵层盖在模型上（与 Live2D 参数解耦，不污染模型）；DropShadow 滤镜随情绪染色

**⑪ 换装 = 模型变体切换**（三项目共识）：同一模型多套贴图 + model.json 变体，切换时新实例淡入旧实例淡出（PIXI alpha 400ms）；贴图可 AI 重绘改色（不动 .moc）——需要美术资产投入

**⑫ 模型升级（活人感上限决定项）**：Shizuku 免费模型是地板不是天花板；"模型素材决定上限"——将来可换精细商业模型或自绘 Live2D 模型（换模型后 P1 ⑥的模型分析器自动接入）

## 四、素材与许可提醒

- Live2D 官方免费模型（Shizuku/hiyori/mao）均有商用限制（个人自用 OK）
- .mtn 动作文件是文本格式（$fps=30 + 参数帧列表），可手写补动作
- 三开源项目所用模型同样是官方演示模型，未提供可商用资产——我们的自写表情路线（exp3 文件）继续沿用

## 五、决策点

1. **P0 立即实施？**（推荐：是。纯代码几小时，零资产，实证收益最大——动作>表情 6 倍 + 微动最硬）
2. **P1 LLM 编排接不接？**（推荐：接。函数调用链路已有，模型分析器一装，未来换模型/加动作全自动）
3. **P2 换装/道具现在投入？**（可后置。①⑨零资产随时能加；⑪换装要贴图资产，等有资产再上）
4. **模型要不要升级？**（长期决定项。决定活人感天花板，换模型后一切自动适配）

## 六、实施顺序建议

P0 ①→③→④→⑤→②（一次会话可完成）→ 用户验收"她活着了" → P1 ⑥→⑦→⑧（动作与说话统一）→ 用户验收"会说会演" → P2 ⑨→⑩（零资产先上）→ ⑪⑫ 等资产决策
