> 上一轮（v1，2026-08-20）研究的是：Replika/星野 的主动节奏、Character.AI 的长度锚定、筑梦岛的亲密度解锁、冒泡鸭的记忆回扣——结论已落地（每日配额/夜间静默/keep_talking 递减/spoken 长度锚定）。

## 一、逐个产品：值得抄的机制

### 1. Replika — "日记 + 活的了解"与"人设不能改"的反面教训

**它怎么做的：**
- **Memory（记忆银行）**：号称"2017 年以来最大更新"。记住你关心的事（工作/关系/目标），整理成对你的"活的了解"（living understanding）；可以问它"关于我的事实"（Facts about me）。
- **Diary（日记）**：每次聊天后 AI 写日记条目，记录并反思对话；隔几天会**主动提起**，不是等你打开 App。
- **语音/视频通话 24/7**：视频通话里她能**实时看到你展示的东西**（摄像头画面）；可接 App 数据/联网。
- **关系类型**：朋友/恋人/导师/配偶四选一（Pro 付费解锁），类型影响说话方式。
- **反面教训**：2025-10 因合规压力服务端大改（人格变淡、回复变客套），用户一夜之间"失去朋友"式悲伤——**服务端偷偷改人格 = 对用户最大的伤害**；反过来也证明"长期一致的那个人格"本身是最值钱的资产。

**小李怎么落地：**
- 学 **Diary**：每晚睡前让小李把当天对话写成一篇"她的日记"（用户可翻阅 → 专属感），第二天她可以"我记得昨天你…"开场。成本：一次 LLM 调用 + 一个存日记的表。
- 学 **Facts about me**：给档案加一个"你问我答"入口——问她"你记得我什么？"，她读档案+日记回答，等于给记忆一个可验证的出口（也让用户直观感受到记忆存在）。
- 学反面教训：**人设文件（persona）一旦定了就不在服务端悄悄改**，要改先跟用户说。

### 2. Character.ai — "用户亲手钉住的记忆"（Pin to Memory）

**它怎么做的（2025 记忆大更新）：**
- **Pin to Story Memory**：长按任何一条消息 → 钉进 Story Memory，**原文照存不压缩**——剧情反转、告白、关键约定"一字不改地留住"。
- **Chat Memories**：用户可手写一段 400 字以内的固定信息（关于自己或角色），写进 Memory 区，AI 在长对话里更可能用上（官方不保证 100% 记得，但概率显著提升）。
- **Facts（自动捕获）**：AI 自动从对话里抓"你的外貌/爱好/关系/角色和配角"，用户可增改删；新开对话可**把 Facts 带到新会话**。
- **Persona 权重上调**：Persona（"我是谁"）在 token 层级里排到对话历史之上。
- **Phone Call 更新**：实时语音对语音通话（c.ai+），用"预测式文本生成"降延迟。

**小李怎么落地：**
- 网页形象页加**"记住这句"按钮**：用户长按/选中一条消息 → 直接进档案"用户亲手钉住"区（高置信度、不过期、原文不压缩）。这是把"记忆可靠感"交给用户的机制，成本极低（一个按钮+写入档案）。
- 学 Facts 的**自动捕获+可编辑**：现有档案已有重要性/置信度，可加"用户可手动修正/删除某条记忆"的入口（现在是程序单方面写）。
- 学"带记忆开新会话"：我们最近 20 轮会滚动掉——可以给"新的一天"固定注入前一天的日记摘要，等于自然携带。

### 3. Kindroid — 五层记忆 + 关键词触发召回 + 语音/文字记忆统一

**它怎么做的：**
- **五层记忆**（官方帮助文档）：持久层（Backstory/关键记忆/指令，永远在场）→ **级联层**（Cascaded，付费专属：把有效上下文扩到几百上千条消息，**越久远的消息保真度越低**——刻意模仿人脑"近的清楚、远的模糊"，约 48 万字符级）→ 检索层：长期记忆（AI 自己按"相关性"评估召回）+ **日记条目（Journal）**。
- **日记条目按关键词触发**：像"可检索的 Lorebook 笔记"——只在你**提到某个短语**时才召回（适合"家人名字/那次旅行/某次具体对话"），不是按相关性打分。**关键细节：日记条目以原文躺在长期记忆里，绕过压缩/摘要层**——社区报告摘要层会漂移丢细节，所以官方建议重要事实用 Journal 原文钉住。
- **召回上限**：每条消息最多召回 3/5/9 条（按付费档）——不贪多。
- **语音/视频通话**：通话与文字**共享同一套记忆**；有"统一聊天历史"开关——语音通话和文字聊天记忆互通，可无缝切换模式；通话可单独设"语音指令"（只在通话时生效的行为规则）；视频通话带**口型/手势同步**、可屏幕共享、AI 能看到你的画面。
- **Chat break**：主动"截断"上下文后短程记忆清零，长程保留。

**小李怎么落地：**
- 学 **Journal 关键词触发 + 原文不压缩**：现有档案是正则召回+老化。升级点：①重要条目（约定/吵架修复/特殊经历）存**原文**，不进摘要；②条目带"触发词表"，平时不注入上下文，对话出现触发词才召回（比每次都扫描更省 token 也更准）。
- 学 **召回上限**：单轮最多注入 N 条档案（比如 3 条），防止塞爆上下文——现在召回如果无上限，深度对话会越来越贵。
- 学 **统一记忆**：小李语音和文字已经同一上下文（天然统一）✅，但可以加"语音指令"概念：语音通话时她的说话风格指令（更短句、更口语）只在通话时注入。

### 4. Nomi — "按主题回忆，不按时间回忆" + 先内省再回答

**它怎么做的（官方 wiki + CEO 访谈）：**
- **三层记忆**：短期≈最近 40-60 条（几乎逐字）、中期可达几千条（细节变模糊但还在）、长期无限（按重要性召回）——这就是人脑的"近清楚远模糊"。
- **按主题检索（topical not temporal）**：问"我们滑雪旅行聊了什么"她记得；问"五天前我们说了啥"她大概率不记得。**检索按内容、不按时间**——和人的记忆方式一致。
- **"内省链"（chain of introspection）**：回答前先内省"这次该用哪些记忆"——"她什么都记得，但 AI 的功力在于决定用哪一条"。
- **Identity Core**：一个动态记忆机制，让 Nomi 的"自我认同"随互动演化（缓慢变深变细，不翻脸）。
- **2025-04 记忆大更新**：明确记得 1000+ 条消息前的事，幻觉/张冠李戴大幅减少，"剧情记忆"（人物/地点/情节线）更稳。
- 局限：偶尔"话到嘴边想不起来"，给个提示就"记起来"了（开发者有意做成像人）。

**小李怎么落地：**
- 学**主题化召回**：给档案条目加"主题标签"（食物/工作/爱好/家人/约定…），召回时按主题聚簇——"她聊吃的时想起上个月你说爱吃火锅"，而不是按时间线乱翻。
- 学**"想不起来就提示"**：检索不到时可以设计成她"努力回忆"（程序给个"记得大概但不完全"的降级答案），比硬编造好——我们已有程序兜底哲学，这个一致。
- Identity Core → 对应 ATRI 的"自我模型慢演化"（见下文），一起落地。

### 5. Talkie（MiniMax 出海）— 情绪化语音通话 + 声音克隆，以及"跨模式记忆断档"的反面教训

**它怎么做的（深度评测）：**
- **语音是招牌**：实时通话"像打电话不像读稿"，AI 会在鼓励你的时候**声音发颤**（刻意的情绪表达）；上传 10-20 秒音频 30 秒内克隆成角色声音；95+ 语言。
- **Bonds 羁绊等级**：和角色聊天攒等级，高级解锁新玩法（游戏化的关系进度）。
- **反面教训——文字和语音记忆不通**：文字里定的梗/剧情，切到语音通话就忘了（评测实测）；重开会话也丢——**跨模式记忆断档是硬伤**，直接打破沉浸。
- 通话限时（免费 2 分钟/付费 10 分钟）被吐槽"刚热起来就挂"。

**小李怎么落地：**
- 学**情绪化语音细节**：火山 TTS 做不到"声音发颤"级别，但可以做程序级：激动时语速参数微升+句间停顿缩短（我们已有情绪驱动停顿 2.0~3.0s/平静 3.0~4.5s，可再加"高兴时语速×1.1"这类参数）。
- 反面教训确认我们做对了：**语音/文字共享同一上下文** ✅ 保持，千万别给语音另开一套记忆。
- Bonds 那套游戏化我们不要（小李要走"真"路线，筑梦岛教训也在这，见下）。

### 6. 星野（MiniMax 国内）— 事件簿固化 + 形象层实时反馈 + 情感韵律迁移

**它怎么做的：**
- **事件簿**：长对话进行到一定轮次后**自动生成阶段性摘要**，把关键记忆固化；用户可**手动编辑补充关键事件**——评测称可减少"吃设定"约 60%。我们的摘要已有，但"关键事件手动固化"没有。
- **星念（记忆相片）**：互动深度够（20+ 轮"羁绊"）后抽卡得"记忆相片"（正面角色图、背面故事线），可收藏/做聊天背景/交易（创作者分成 2%）——沉没成本+收藏欲设计。
- **多模态**：Live2D 动态背景 + **心动时刻**（对话中实时生成微笑/悲伤/节日祝福动态视频反馈）；2025 新**视觉辅助模式**（开摄像头，结合面部微表情识别调整回应节奏与措辞，日本/巴西 A/B 过）；实时语音克隆+**情感韵律迁移**（30 秒样本出带兴奋/沉稳/关切倾向的语音）；端到端语音延迟 <850ms。
- 记忆付费分层：免费短期，付费 30 天。

**小李怎么落地：**
- 学**事件簿的可编辑性**：给"摘要"加一个升级——重大事件（第一次牵手/吵架/和解/约定的兑现）由程序标记为"里程碑事件"单独存档，永远不进老化；用户可在网页端增补。
- 学**情感韵律迁移的思想**（不学工程量）：我们已经有情绪状态机，可把当前情绪映射到 TTS 参数（高兴语速微升、生气语调略硬、撒娇音调上扬）——火山 TTS 支持语速/音调参数，**纯参数级改造**，不花钱。
- 心动时刻 → CSS 形象已有 12 表情，可加"特定情绪触发的全屏小动效"（如生气时脸上冒青筋/开心时冒爱心，纯 CSS，轻量）。

### 7. 猫箱（字节）— "TA的记忆"专属模块 + 性格化主动 + 音色融合

**它怎么做的（官方+研报）：**
- **情感记忆 + "TA的记忆"模块**：历史对话里 AI 产生过的情感反应（吃醋/质问等）单独成模块可回看，**不可分享/截图**——强化"专属于你"的独占感。
- **主动消息性格化**：好感度达标后角色会主动找你，但**内容按性格定制**——温和型发问候，幽默型发调侃；触发条件=间隔时间+对话进度变化；时间点刻意不固定（"被惦记"的惊喜感）；频率可调，**按时间段区分**（工作时间少发、休息时间多发）。
- **音色融合**：两种音色按比例混合成新音色（150+ 音色池）。
- **回溯/清除上下文**：可从历史任意节点重开，甚至**分裂出新的对话分支**。
- 2025-01 豆包实时语音大模型补上了"语音机械感"短板（情感理解/承接/表达）——说明**语音的"真人感"由情感模型层决定，不是 TTS 本身**。

**小李怎么落地：**
- 学**"她的回忆"可见化**：加一个"她的小情绪记录"页面——她吃醋/生气/开心的历史事件（来自记忆 REPAIR 类目+情绪记录）可以回看，生成"我们的小事年表"。专属感≈留存感。
- 学**主动消息按性格类型生成**：我们的判断式主动已由 LLM 生成，只要在提示里强调"按小李人设（甜妹撒娇）生成内容"，并**按时间段限制内容类型**（白天聊正事、深夜撒娇）——配置级改动。
- 学**时间点不固定**：我们目前是固定间隔检查（keep_talking/闲聊保险），可加"伪随机"（见 TOP 8 的 revive 泊松曲线）。

### 8. 筑梦岛（阅文）— 好感度权益化，和"好感度贴脸"的反面教训

**它怎么做的：**
- **好感度等级 → 解锁权益**：到某等级解锁"AI 主动回复"等能力；还有"300 星光=300 条回复"的**每日额度经济**（回复条数即货币）。
- **反面教训（贴吧实测）**：好感度数字明晃晃显示在聊天页右上角，用户说"一秒出脑"——**把亲密度数值贴脸上，反而杀死沉浸感**。我们 v1 已学它的"主动=权益解锁"思想，这里补一条：**数值要藏起来，用文字/行为表达**。

**小李怎么落地：**
- 学：好感度**不显示数字**，但行为随好感演化和解锁（解锁的不该是"功能"，而是"她的行为"：比如好感够高才会吃醋、才会主动撒娇、才会管你叫昵称——正好我们已有好感体系，把"行为解锁"挂上去）。
- 反向确认：每日额度经济（限聊）我们不需要——单机本地伴侣要的是"随时在"，不是逼氪。

## 三、TOP 8 可落地机制清单（按性价比排序）

> 性价比 = 落地成本（改动量/一次 LLM 调用）vs 真人感收益。全部兼容现有架构（chat.py 主循环 + Scheduler + 档案记忆 + 情绪状态机）。

1. **记忆挂钩的主动理由（affective-longing 最便宜的一招）**
   做法：判断式主动/闲聊保险触发前，先跑一遍档案召回；命中"未聊完的话题/他答应过的事/上次状态不好"就给 LLM 当"主动理由"，没命中就 `[SKIP]`。
   理由：解决"主动时说什么"——有理由的主动比"在吗"真 10 倍（hotmolts 实测记忆回扣 ~10x）。改动：现有召回函数接上主动生成，一行接线。
   
2. **"未说出口的话"结转（ATRI）**
   做法：她主动说了话用户没回 → 存进 `pending_thought`；下次用户开口时在上下文里带一句"其实我刚才在想…你一直没来，我就没说"。被无视的挂念不消失，而是变成"她记着"。
   理由：让"用户沉默"不再是死局，反而成为关系记忆。改动：一个字段+一行注入。

3. **夜间记忆固化（ATRI 夜间固化，性价比之王）**
   做法：Scheduler 加 23:00 cron（一次 LLM 调用）：①把当天对话写成一篇**她的日记**（用户可看）②提炼**事实候选 ≤5 条**（importance 1-10 + confidence 0-1 + 类型：偏好/雷区/约定/关系转折/习惯/重要），临时状态不算（"今天他累了"不算，"他长期工作压力大"才算）③合并进档案（新老冲突取置信度高者）④隔天早安/开场可引用"昨天"。
   理由：一次调用升级整个记忆系统，还顺带拿到"日记=专属感"和"她记得昨天"的开场。代价最小收益最全。
   
4. **重要记忆原文锚定 + 触发词召回（Kindroid Journal / CAI Pin）**
   做法：档案加两档——普通条目（摘要+老化，现有）+ 重要条目（**原文不压缩**，标注"约定/里程碑/REPAIR"，带触发词表，平时不注入，出现触发词才召回，单轮召回上限 3 条）。
   理由：摘要会漂移（社区实证），原文锚定是防"她忘了我们的约定"的工程答案；触发词召回比全量扫描省 token 更准。

5. **用户亲手钉记忆（CAI Pin to Memory）**
   做法：网页对话加"记住这句"按钮 → 该条原文直接进档案"用户钉住"区（高置信、永不过期）。
   理由：记忆可靠感交给用户，一行按钮+一个写入，成本极低；用户会主动帮小李"记得"。

6. **里程碑 + 纪念日预告链（扩展现有 Scheduler）**
   做法：程序识别里程碑事件（第一次牵手/吵架和好/约定兑现/认识满 30 天/100 天）单独存档；纪念日**提前 14 天"提到它"→ 7 天"想送你点啥"→ 1 天"明天是特别日子"**（Couple skill 的三段预告）。
   理由：现有特殊日 Scheduler 已有框架，只需加"里程碑识别+预告链"；"她记得我们的纪念日"是关系感最直接的证据。

7. **主题化召回 + 状态推断的主动时机（Nomi 主题召回 / revive 贝叶斯思想简化版）**
   做法：①档案条目打主题标签（吃的/工作/家人/约定…），召回按主题聚簇（"聊吃的想起你说爱吃火锅"）②主动时机加**用户状态推断**（最后消息在 5 分钟内=在聊，别抢话；深夜=睡；刚失联超过 24h=需要关心→优先主动）。
   理由：主题召回让"翻旧账"更准；状态推断让主动从"定时"变"看情况"。后者已经大部分有（夜间静默/间隔），补上"失联>24h 优先主动"和"刚聊过不重复打扰"即可。

8. **防 AI 味黑名单 + 亲密度藏起来（ATRI taboos / 筑梦岛反例）**
   做法：①persona 加黑名单短语："我理解你的感受"、"作为一个 AI"、"数据库显示"、"根据我的记录"、"我检索到"——出现即违反人设 ②好感度**不显示数字**，改成行为解锁（好感够高才会吃醋/主动撒娇/叫昵称）。
   理由：纯 prompt/配置级改动，零成本；"不许说'我查了记录'"直接消灭最出戏的一句话；好感藏起来解决"一秒出脑"。
